# Octree build, find, extract, check_tree (slice S6b, 2026-10-29)

Status: **Tested, not Parity** (no CUDA toolkit here, the reference rules are inferred, see [vulkan_octree_foundation.md](vulkan_octree_foundation.md)). Class `gpu_voxels::vulkan::Octree` (`Octree.h`, `src/Octree.cpp`), node formats in `OctreeFormat.h` (host) and `shaders/octree_nodes.glsl` (GPU). Decision background: pointer-faithful route (Q19), read-only core first (Q20), all variants (Q21): deterministic and probabilistic trees are done, the Morton voxel list is not (needs 64-bit list ids, later). Dynamic operations (insert, propagate, rebuild) are slice S6d; collisions and the load balancer are S6c.

## API (read-only core)
| Call | Contract |
|---|---|
| `Octree(Context&, OctreeKind)` | throws `VulkanError` without `bufferDeviceAddress`; starts as the empty tree (root block only: status UNKNOWN, probabilistic occupancy -128) |
| `build(span<OctreeVoxel>)` / `build_from_ids(span<uint64_t>)` | replaces the tree; duplicates merged; coordinates >= 2^14 / ids >= 2^42 are dropped and counted (`dropped_count()`; CUDA only asserts); at most `kMaxVoxels` = 16 776 960 inputs per build (`Primitives::kMaxSortElements`); blocking |
| `clear()`, `voxel_count()`, `memory_usage()` | back to the empty tree; distinct voxels; bytes and allocated blocks per level |
| `find(span<uint64_t>)` | GPU batch lookup; the walk from the root stops at a leaf, a node without children or a **uniform node** (no PART flag, CUDA treats such nodes as leaves although it keeps their children); result `(level, status, occupancy)`, level 255 = id outside the tree |
| `extract(OctreeExtractOptions)` | GPU extraction with CUDA's rules (below); `min_level` 0..13, 256-entry status selection (empty = all); result order unspecified |
| `dump()` / `check_tree()` | host walk over all chunks read back: nodes reachable from the root ordered by (level, id) / structural validation, throws listing the first problems |
| `chunk(level)`, `set_max_groups_x()` | raw chunk buffer for tests/tools (writing can corrupt the tree), test hook that caps the x group count so the 2D dispatch path is exercised |

## Memory layout (native, no promise of CUDA compatibility, Q22)
One chunk (buffer) per level, blocks of 8 sibling nodes, 15 levels (0 = voxels, 14 = root; the root block holds the root and seven unused nodes, as in CUDA). Inner nodes: deterministic 8 bytes (`status | flags<<8 | child[0..15]<<16`, `child[16..47]`), probabilistic 12 bytes (`status | flags<<8 | occupancy<<16`, `child` low 32, `child` high 16); leaves: 1 byte (status) / 2 bytes (status, occupancy). A child pointer is the **device address of the child block, low 48 bits, sign extended from bit 47 when read**: the Intel driver returns canonical addresses with the upper 16 bits set, the first version (zero extension) failed on that ([K29](../known_issues.md)). Every chunk is checked at creation: 16-byte aligned and canonical, else the build throws. A full tree of 1 M random voxels in a 200^3 cube (940 k distinct) takes 13 MiB (deterministic) / 22 MiB (probabilistic).

## Build (bottom-up like CUDA, no propagate pass)
1. Morton ids (`octree_morton_ids`), invalid coordinates get the sentinel 2^42 and are counted, 64-bit radix sort (43 key bits, 6 passes; new primitive `Primitives::sort_pairs64`), distinct ids (heads + scan + compaction).
2. For every level 0..14: heads of the groups that share a parent (`id >> 3(level+1)`), exclusive scan = block index, read back the block count, allocate the chunk, then **one thread per group builds the whole block of 8 nodes** (no atomics, no initialisation pass): occupied children get their final status from their own child block (read through the device address), all other slots are fillers. The element index of a group in the level below is also the index of its child block, as in CUDA.
3. Result = the tree CUDA's build + propagate leaves behind for a fresh tree (UNKNOWN fillers, getNewStatus / max occupancy rule, STATIC bits OR-ed, flags zero). The general propagate kernels are not needed before S6d, where the equality "build == build + propagate of the same set" becomes a test.
Cost: two submits and one read-back per level (CUDA synchronises per level as well).

## Extract (replaces the load balancer for the read-only core)
Rules of the CUDA kernel (`kernel_config/Extract.cuh`): start at the children of the root; a selected node is emitted when it is uniform (no PART) or sits on `min_level`; a PART node above `min_level` is refined; a level 1 node emits its selected leaves. Implementation: level-synchronous wavefront, one invocation per (work item, node), atomic counters for the next work items and the output, two traversals (count, then write exactly) like CUDA's `count_mode`; work items per level are bounded by the number of blocks of that level's chunk.

## Verification
- `test_vulkan` (+17 cases: 3 sort64, 14 octree) and `test_octree_reference` (+5 format cases): every tree built by the GPU is compared node by node (`dump()`) with the independent reference, plus `check_tree()`, memory counts, `find` of every voxel / neighbour / random id / ids outside, `extract` for several `min_level` x status selections (all combinations for five thorough sets, three representative ones otherwise); sets: hand-derived trees (single voxel, corners, duplicates, full 2^3 / 4^3 blocks, two voxels meeting at the root, around 1024, dropped voxels), random sparse / dense / far-corner sets up to 2 500 voxels, cubes with holes, both kinds, 1 M voxels with `check_tree` and probes; the raw node memory equals the host encoding bit for bit; flags set on every node do not disturb status or pointers; `check_tree` finds 11 injected corruptions and `find` survives a PART node without child pointer (a null dereference loses the device on Intel) (pointer outside / misaligned / shared / wrong level, lost children, wrong status or occupancy, wrong LAST_LEVEL, PART or LAST_LEVEL on a leaf); a second context without the feature makes the constructor throw; the 2D dispatch path is run with a 3-group cap.
- Mutation check: 138 mutations (32 node formats in GLSL, 13 build kernel, 9 find, 17 extract, 9 small kernels and the Morton ids, 30 host code, 13 host format, 5 reference lookup/extract, 11 sort64 and its primitive code): 137 killed, 1 provably equivalent for fresh trees (GN25: the "all children UNKNOWN" branch of the deterministic parent rule cannot occur below a node that holds an occupied voxel; the host version of the same rule is tested against the reference). The first run found redundant masks (removed), a gap in `addressable` (wrap-around, fixed) and missing tests (flag isolation, raw memory format, null child pointer in `find`, full-range ids in `build_from_ids`, LAST_LEVEL on a leaf, zero-size range), all added.

## Not verified / limits
Nothing ran under CUDA, so equality with the CUDA tree is inferred. Limits: 16 776 960 input voxels per build (the sort limit, tested at the limit and one above), one chunk may not exceed the device's `maxStorageBufferRange` (1 GiB here; chunks are only addressed through pointers, but `DeviceBuffer` applies that limit), the group count limit is handled by the 2D path (only exercised with the test hook: this device allows 4 G groups). Flags are only checked for isolation, their meaning arrives with S6d. The `uniform node keeps children` state of CUDA appears only for full blocks (children are kept, `find` ignores them, `dump` shows them).
