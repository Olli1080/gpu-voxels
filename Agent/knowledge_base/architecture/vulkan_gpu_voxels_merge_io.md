## Merge
`uint32_t merge(const GpuVoxelsMap& other, Offset3i voxel_offset = {}, std::optional<uint8_t> new_meaning = {})` returns the number of voxels / entries that were not merged because they lie outside after the offset (CUDA returns a bool). Everything not in this table throws `VulkanError` "the operation 'merge of <source type>' is not supported by the map type <target>" (CUDA logs and returns `false`; D2 of the checklist).

| Target <- source | What happens |
|---|---|
| bit / prob. / distance map <- bit list, counting list | the coordinates of all entries are inserted as occupied (CUDA `insertCoordinateList`; the list's counts and bits are not looked at). **No offset and no `new_meaning`** (CUDA: offset gives an error and `false`, the meaning is ignored): both throw. Coordinates outside the map are counted. The list may have other reference dimensions, the voxel side lengths must be equal |
| bit list <- bit list | all entries are appended moved by the offset, bit vectors OR-ed into existing entries; `new_meaning` replaces the bits of the new entries by that one bit |
| bit list <- counting list | new entries get no bits (`new_meaning`: that bit); CUDA the same, so entries without any bit exist afterwards |
| bit list <- bit map | the occupied voxels (any bit but `eBVM_FREE`), bit vectors copied (`new_meaning`: only that bit). Same dimensions, **no offset** (CUDA applies the offset to the ids after copying, which does not move the voxels) |
| counting list <- counting list | counts added, wrapping like int8 (100 + 100 = -56) |
| counting list <- bit list | new entries get count 0 (CUDA: default `CountingVoxel`); no `new_meaning` (throws, CUDA ignores it) |
| octree <- anything, anything <- octree, map <- map, list <- prob. / distance map | not supported |

Rules for all: `&other == this` throws ("a map cannot be merged into itself"; CUDA locks the same mutex twice); a different voxel side length throws ("merge: the voxel side lengths differ"); list targets need equal reference dimensions ("reference dimensions differ"); the source is never changed; entries whose moved voxel lies outside the reference map are dropped and counted (CUDA wraps the coordinates and keeps them).

`merge_metric(other, Point3f, new_meaning)`: the offset in voxels is `floor(m / side)` for list targets (CUDA `mapToVoxelsSigned`) and the **truncation toward zero** for map targets (CUDA casts), so -0.05 m with 0.1 m voxels is -1 voxel for a list and 0 for a map. A value that is not finite or at least 2^31 voxels in size throws.

The list merge is done on the host (the entries of the source are downloaded, moved, uploaded and sorted into the list by the existing `make_unique`); it is meant for map building, not for every frame. Class level: `BitVoxelList::merge`, `CountingVoxelList::merge`, `VoxelListBase::merge_entries`, `assign_entries`.

## Disk
`bool write_to_disk(path)` / `bool read_from_disk(path)` of `GpuVoxelsMap`: `false` and an error log when the file cannot be opened or written, or is refused (CUDA also returns `false`, but reads some problems partly). A read replaces the whole content and leaves the target unchanged when it fails. The class level functions are `write_map_file` / `read_map_file` and throw `MapFileError` (a `VulkanError`) with the reason.

Native format, little endian: header of 48 bytes (magic `GVLMAP\0\1`, version 1, `MapType`, dimensions, voxel side length, two reserved words, count), payload, FNV-1a 64 bit checksum of header and payload. Payload: bit map 8 words per voxel; prob. map int8 per voxel; distance map one packed word per voxel; bit list ids, coordinates, 8 words per entry; counting list ids, coordinates, int8 counts. Full layout in `MapFile.h`. A file is refused for: too short, wrong magic / version, other map type, other dimensions (lists: reference dimensions), other voxel side length (CUDA warns for maps and continues), non-zero reserved words, a count that does not fit the type or length, truncation, data after the end, a wrong checksum, and (lists) entries that are not valid (ids not ascending, id not the index of the coordinates, coordinates outside), distance words with bits above bit 29.

Octrees use `OctreeNativeStorage` (S6e, its own checked format); a read restores the voxel side length of the file. Files of other map types and of the other octree kind are refused.

**CUDA's own files are not read.** They are raw dumps (maps: the device memory with a short header; lists: ids, coordinates and voxels; the prob. and distance voxels have layouts of their own) and no file written by CUDA exists to test against. The `OctreeStorage` interface already shows how a reader can be added behind the same calls.

## Verification
- `tests/vulkan/test_gpu_voxels_merge.cpp` (8 cases): list merges for both kinds, both sources, five offsets (none, mixed, everything outside, partly outside, negative) and meanings (none, 9, 200) against a **host model built from the downloaded states** (OR / int8 sum / zero payload rules, the dropped count, the source unchanged); int8 wrap-around; the bit map as source with the host's definition of occupied; maps from lists (smaller map than the reference map, counts of outside voxels, bit map against the host reference, others against the class used directly); all 49 combinations of types (supported ones do not throw, the others throw with source and target named and change nothing); the argument errors; metric offsets (floor / truncation, every axis, not finite, exactly 2^31); the checks that the list classes make themselves; `assign_entries`.
- `tests/vulkan/test_gpu_voxels_disk.cpp` (8 cases): round trips of all seven types (a read replaces, empty map, writing over a file); **the bytes of a bit map, a bit list, a counting list and the payloads of the prob. and distance map against files built by hand in the test** (header, payload, checksum written out again); every damage of every field of the header, truncations, appended bytes, flipped payload and checksum bytes for the five formats, each with its message and the target unchanged; forged files with a valid checksum but invalid entries or distance words; files of other types, dimensions and side lengths; missing files, a directory and a missing directory as target; octree files; the upload functions of the three maps with wrong sizes.
- Mutation runner `tools/mutation/mutate_s7d_merge_io.py` (91 mutations): **all 91 killed**, none equivalent (log `tools/mutation/logs/s7d_merge_io.log`). Gaps closed with tests while writing it: meanings of 32 and more (the word index of the new bit), negative counts in files (sign extension), exact boundaries of the coordinate checks, class level checks that the façade checks hid (self merge, side length, dimensions), the sign extension of the device words after an upload, `assign_entries` of both list kinds. One mutant did not build (a removed variable) and was repeated with another pattern. Not tested: the limit of more than 2^24 entries in `entries_problem` (no mutant for it)
- **Not verified:** CUDA parity (neither merge nor the formats); a list with more than 2^24 entries (the limit of `assign_entries` / the sort primitive is not exercised); maps of more than a few million voxels through the files (the whole file is held in host memory).
