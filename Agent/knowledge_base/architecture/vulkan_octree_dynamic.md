# Octree dynamic updates: insert, propagate and rebuild (slices S6d-2 .. S6d-7, 2026-10-31 / 2026-11-02)

Status: **Tested, not Parity** (the CUDA rules are inferred from reading, nothing ran under CUDA). Deterministic and probabilistic trees, insert of single voxels (level 0) and of whole nodes of any level 0 .. 13, hard and soft mode, `UPDATE_SUBTREE`, `rebuild` with a memory / garbage policy. Extends `Octree` ([vulkan_octree_build.md](vulkan_octree_build.md)); design and findings: [S6d design](../../Analysis/2026-10-31_s6d_design.md). Still open: the free-space bounding box and the sensor free-space insert (S6f).

## API
| Call | Contract |
|---|---|
| `insert(span<OctreeVoxel>, OctreeDatum, propagate_now = true)` / `insert_ids(span<uint64_t>, ...)` | CUDA `insertVoxel` with the hard reset data, level 0. Deterministic: the voxel becomes occupied or free. Probabilistic: a NEW voxel is SET to occupancy 127 (occupied) / -127 (free), an EXISTING one is UPDATED (old occupancy, UNKNOWN counts as 0, plus 127 / -127, clamped to -127 .. 127). Duplicates are merged, coordinates >= 2^14 / ids >= 2^42 dropped and added to `dropped_count()`. New blocks become **new chunks** (one per level that needs blocks). `voxel_count()` is not updated |
| `insert_nodes(level, node_ids, datum, mode, propagate_now = true)` | S6d-3b: the same for whole nodes of `level` 0 .. 13 (ids on that level, below 8^(14 - level), the rest dropped and counted), e.g. free space as big cubes. Deterministic: the node gets the occupancy bits of the datum and loses PART (soft cuts as well). Probabilistic: the occupancy is SET to 127 / -127 (not added); `Hard` clears PART (the subtree is cut: its block stays allocated and reachable but stale), `Soft` keeps PART and sets UPDATE_SUBTREE on an existing node that has PART, the next propagate then updates the subtree. If the path ends above the level on a node without PART, blocks are created down to the level. Level 0 = `insert_ids` |
| `set_gpu_sort_limit(ids)`, `set_bounded_propagate_limit(ids)`, `test_set_pending_bound(ids)` | test hooks: the batch size above which ids are sorted on the GPU (default 20 000), the number of inserted ids up to which propagate runs in one batch (default 131 072, 0 = always the exact path), an overwrite of the bound (a bound that is too small makes `propagate()` throw), and `set_exact_list_threshold(bytes)` (default 4 MiB: lists of the exact path that would be bigger are counted first; 0 = always, UINT64_MAX = never) |
| `propagate()` | recomputes the nodes that carry NEEDS_UPDATE from their children (CUDA `propagate`), level by level on the GPU; nothing to do without pending updates. Without `propagate_now` the statuses are inconsistent until it runs |
| `pending_update_count()` | nodes with NEEDS_UPDATE reachable through PART nodes (0 after `propagate()`; a subtree below a cut node keeps its flags, nothing visits it), read back and walked on the host |
| `rebuild()` | S6d-4, CUDA `rebuild` (extract every cube, build a fresh tree): propagates pending updates, then copies the nodes reachable through PART nodes into new chunks (one per level, exactly sized) and releases the old chunks: garbage and the many chunks of earlier inserts disappear. Nodes keep status, occupancy and COLLISION bits, flags are clear; a node without PART loses the child block it may still point to (dead data: `find`, `extract` and collisions stop at it). `voxel_count()` / `dropped_count()` are kept. If it throws (corrupt tree: a block referenced twice, or an allocation failure) the tree is unchanged |
| `needs_rebuild()`, `set_rebuild_policy(OctreeRebuildPolicy)`, `rebuild_policy()` | CUDA `needsRebuild`: true when the memory of all chunks reaches `max_bytes` (default 200 MB as in CUDA, 0 = no limit). Addition of this port: `max_garbage_fraction` (default 0 = off, at most 1): true when garbage blocks make up that fraction of the bytes; evaluating it counts the garbage on the GPU (see `memory_usage()`), but only while an insert may have left garbage. Nothing rebuilds automatically: the caller checks after an insert (as CUDA's `NTreeProvider` does). A fraction outside 0 .. 1 (or NaN) throws and changes nothing |
| `memory_usage()` | `garbage_blocks[level]` (allocated blocks no node points to any more) and `chunks`. S6d-6: counted on the GPU while an insert may have left garbage (0.25 ms for 299 593 garbage blocks, before 30 ms: the host walk over a read-back snapshot). The reachable blocks are walked level by level from the root through every node with a child pointer (PART or not: the pointer of a uniform node keeps its block reachable, as in the host walk of `check_tree`), all levels in ONE batch: the kernel `octree_garbage_scan` reads the count of its level from a small counter buffer, appends the child addresses to the list of the level below (two ping-pong lists sized by the allocated blocks of each level) and counts them; one read back at the end. garbage = allocated - reachable per level. If a level holds more reachable blocks than were allocated (a block referenced twice: a corrupt tree) the counts are not used and the host walk answers instead (`test_garbage_host_fallbacks()` counts that). Test hooks: `test_set_host_garbage_count(true)` forces the host walk |
| `check_tree()` | the status rule "equals the rule applied to the children" now only applies to nodes with PART that are reachable through PART nodes (a node without PART may own stale children, and below it nothing is recomputed: a subtree created and cut before a propagate stays as it is), in a probabilistic tree it ignores STATIC / DYNAMIC (a dynamic update marks nodes DYNAMIC where the build says STATIC); unreachable blocks are a problem only while no insert replaced a child pointer |

## Algorithm (a different schedule than CUDA, the same result)
Insert (S6d-5: two submits and one read back): (1) ids sorted and made distinct: on the host (`std::sort` + `unique`) up to `gpu_sort_limit` = 20 000 ids, above that on the GPU (radix sort of the 42 bit keys, the build's heads + scan + compaction, one read back of the distinct count). (2) **Walk** kernel per voxel: from the root while the node has PART and the level is above 1, setting NEEDS_UPDATE on every visited node and the end node; `info[i]` = end level, node address, kind (0 = the leaf exists, 1 = new blocks needed) and a counter (`stats[14]`) of end nodes that still own a child block (those blocks become garbage). (3) The **count** kernel (same batch, after a barrier) gives the number of new blocks of every level 0..13 in one pass (a voxel is the first voxel of a new block when it has kind 1, its end level is above the level and it does not share `id >> 3(level+1)` with its predecessor; summed per work group in shared memory, one atomic add per group and level into `stats[level]`); one read back of the 15 counters, then one new chunk per level that needs blocks. (4) One batch for the rest: from level 13 down to 0 a **heads** kernel marks the first voxel of every new block of the level, an exclusive scan gives the block indices, then the **link** kernel: the head voxel of a new block initialises its 8 nodes (CUDA `insertNode`) and writes PART and the child address into its parent (the node in the new block one level up, or the node the walk ended on): one block per parent, one head per block, so every node has exactly one writer and no atomics are needed. (5) **Leaves** kernel (target level 0): new leaf = DYNAMIC | datum, existing leaf = (status & ~(occupancy bits | PART)) | datum, atomics on the leaf word only. For a target level above 0 the walk stops at max(target, 1), kind 2 = the walk ended on a node of the target level (it is set), only the levels from the target up get new blocks, and the **nodes** kernel applies the datum to the new or existing node of the target level (single writer per node, ids are distinct node ids).
Propagate (S6d-5, two paths): the **bounded** path is taken while at most 131 072 ids were inserted since the last propagate and no soft node insert happened (`pending_bound`: every inserted id marks at most one node per level, so the lists can be sized from it, level 1 eight times as large because every PART child of a flagged level 2 node is recomputed): all levels run in ONE batch, the kernels read and write the per-level counts in a small GPU buffer (a thread beyond the count returns, a record beyond the capacity is counted but not written, the counts are checked once at the end and a violated bound throws: an internal error, never an out-of-bounds write). The **exact** path (soft inserts reach whole subtrees through UPDATE_SUBTREE, big batches would need big lists) is the earlier schedule with a read back per level; since S6d-7 its work lists have the size they need: a list of the next level takes at most 8 entries per node of this level, which is fine for small lists (allocated with that size, the number of entries read back after the pass), but for a million pending ids those lists were 8 times too big (several hundred MB where about 65 MB are used) and allocating them was 70 % of the time (measured: 8.6 of 12 ms; the read backs were only 0.7 ms). A list that would take more than 4 MiB (`exact_list_threshold`) is therefore sized exactly: a **count pass** of the same kernel (push constant `count_only`, changes nothing, counts into `counter[1]` the children that would enter the next list; the condition `enters_next_list` is shared with the real pass, and neither expansion nor the subtree update touches PART or the flags of a child with PART, so counting before the pass gives the number the pass will list) runs first, one more round trip for that level only. A real pass that lists more nodes than were counted throws (internal error, no write past the list). Both run the same kernels: **top-down** one dispatch per level 14 .. 2 over the work list of flagged PART nodes (a child without occupancy bits takes over from its parent, a child without PART loses the flag, a flagged PART child joins the next list; on level 2 every PART child joins because level 1 nodes are always recomputed), then the **level 1** kernel (invalid leaves take over from the node, the node is recomputed from its leaves), then **bottom-up** from level 2 to 14 (the node is recomputed from its children, flag cleared). The work lists hold 16 byte records (address, inherited UPDATE_SUBTREE): a node passes `subtree` (its own flag or the inherited one) to its children; probabilistic children that are not fresh are then changed (a child with PART takes the parent occupancy, a child without PART is updated with it, clamped), level 1 nodes update their leaves the same way (an invalid leaf gets it twice, as in CUDA), and all children below a `subtree` node are visited flagged or not. NEEDS_UPDATE and UPDATE_SUBTREE are cleared together. No busy waiting.
**The two node rules** (`octree_dyn.glsl`, selected by `OCT_PROB` in the `_det` / `_prob` wrappers of every shader): deterministic "taking over" = every bit except PART / LAST_LEVEL from the parent (so STATIC / DYNAMIC are copied), recompute = CUDA `getNewStatus` (STATIC / DYNAMIC OR-ed, LAST_LEVEL on level 1). Probabilistic "taking over" = the occupancy of the parent and the status UNKNOWN, recompute = maximum occupancy of the children, PART unless all children have exactly that occupancy and none has PART, status = (status without PART and occupancy bits) | PART? | UNKNOWN; LAST_LEVEL, STATIC and DYNAMIC are not recomputed. A probabilistic tree built by inserts therefore differs from a fresh build in more than STATIC / DYNAMIC: occupied leaves are UNKNOWN there (CUDA `_updateStatus`) and STATIC-only in the build (CUDA `setOccupied`).
**Rebuild** (`octree_compact_scan`, `octree_compact_copy`, wrappers `_det` / `_prob`): step 1 walks the live blocks level by level from the root (14 .. 1): one invocation per (block, slot); a node with PART appends its child block address to the list of the level below (atomic counter, read back per level) and remembers that index in a `link` array, every other node gets no link. The capacity of the next list is bounded by the allocated blocks of that level, the counter keeps counting past it, so a block referenced twice is reported on the host instead of overflowing. Step 2 allocates one exactly sized chunk per level and copies all levels in one batch: block j of a level goes to position j of the new chunk, an inner node keeps status, flags and occupancy, with PART its child pointer becomes `new base of the level below + link * block size`, without PART it becomes 0; leaf blocks are copied word by word; the root block is rewritten in place. The old chunks are released only after the batch succeeded.
Differences from CUDA: ids are deduplicated and sorted on the host or the GPU (CUDA requires sorted distinct ids), one chunk per level and insert instead of one allocation, the walk marks nodes with atomics instead of "the first thread of a shared path", propagate is a wavefront instead of the load balanced queue. CUDA `rebuild` extracts the cubes with the user-settable `m_extract_status_selection` (a restricted selection would drop nodes), loses a root without PART (the root is never extracted), frees the old tree before building the new one and re-derives the inner statuses by insert + propagate; this port always keeps every node, keeps the root, compacts block by block (peak memory = old tree + live part) and, because a consistent tree already satisfies the recompute rules, leaves the inner statuses as they are (STATIC / DYNAMIC bits are not normalised).

## Timings
Measured 2026-11-01 on the RTX 4090, Release build without validation layer, 1 M voxel base tree, minimum of 3 ([report](../../Analysis/2026-11-01_octree_dynamic_timings.md), `DISABLED_OctreeDynamicTimings`): before S6d-5 an insert cost 2 - 4 ms for 1 to 10 000 voxels (latency bound by about 60 blocking round trips, propagate added about 2 ms) and 1 M voxels 63 - 73 ms (52 ms host sort); after S6d-5 (two submits per insert, GPU sort above 20 000 ids, one-batch propagate) an insert of 1 to 100 voxels costs 0.2 - 0.3 ms plus 0.3 ms propagate, 10 000 voxels 0.7 - 0.8 ms, 100 000 voxels 1.4 - 1.8 ms, 1 M voxels 9 ms (dense) / 18 - 20 ms (sparse), a series of 200 inserts of 1000 voxels with propagate has a median of 0.6 - 0.7 ms (before 4.6 - 5.7 ms), `insert_nodes` of 10 000 level 3 nodes 5 - 6 ms, `rebuild()` 3 - 22 ms for 14 - 344 MiB, and a tree of 1000 chunks answers `find` / `extract` as fast as the rebuilt one: the rebuild is about memory and garbage, not query speed. 100 inserts of free voxels into a dense cube leave 299 593 garbage blocks (4 -> 7 MiB), the rebuild brings the tree to 2 MiB; `memory_usage()` and `needs_rebuild()` with the garbage fraction walked the tree on the host (32 ms for 11 MiB) until S6d-6, which counts on the GPU (0.25 ms). S6d-6: `memory_usage()` / `needs_rebuild()` with the garbage fraction 30 -> 0.25 ms (same count, 299 593 blocks). S6d-7: the propagate of 1 M pending ids (exact path) 13.4 -> 5.1 ms deterministic and 16.2 -> 6.9 ms probabilistic in the sparse volume, unchanged in the dense one (2.1 - 2.6 ms).

## Not verified / limits
No CUDA comparison (the reference is derived from the same reading: a shared misunderstanding would not be found, golden data are needed for that, Q5). The CUDA free-space bounding box (`free_bounding_box`, reset data with UPDATE_SUBTREE in the reset flags: the node is set but the subtree flag is not) and the sensor free-space insert are not ported (S6f); the log-odds values of the datum (127 / -127) are the CUDA `getOccupiedData` / `getFreeData`, not the sensor model (+100 / -10 of `CommonValues.h`, which belongs to the sensor pipeline S6f). Garbage and chunks are released only by `rebuild()`, which the caller starts (`needs_rebuild()`); there is no automatic rebuild after an insert. Insert batches are limited to `kMaxVoxels`; every insert allocates up to 14 chunks (one per level) until the next rebuild. `rebuild()` needs memory for the old tree, the live part and the work lists at the same time and reads back one counter per level; a corrupt tree (a block referenced twice) is detected by a count check, not repaired. The byte limit counts the bytes of all chunks (CUDA counts allocated nodes). Timings: see below.
