# Octree dynamic updates: insert and propagate (slices S6d-2 and S6d-3a, 2026-10-31)

Status: **Tested, not Parity** (the CUDA rules are inferred from reading, nothing ran under CUDA). Deterministic and probabilistic trees, hard insert of single voxels at level 0. Extends `Octree` ([vulkan_octree_build.md](vulkan_octree_build.md)); design and findings: [S6d design](../../Analysis/2026-10-31_s6d_design.md). Still open: soft insert, `UPDATE_SUBTREE`, higher target levels, the free-space bounding box (S6d-3b), `rebuild` (S6d-4).

## API
| Call | Contract |
|---|---|
| `insert(span<OctreeVoxel>, OctreeDatum, propagate_now = true)` / `insert_ids(span<uint64_t>, ...)` | CUDA `insertVoxel` with the hard reset data, level 0. Deterministic: the voxel becomes occupied or free. Probabilistic: a NEW voxel is SET to occupancy 127 (occupied) / -127 (free), an EXISTING one is UPDATED (old occupancy, UNKNOWN counts as 0, plus 127 / -127, clamped to -127 .. 127). Duplicates are merged, coordinates >= 2^14 / ids >= 2^42 dropped and added to `dropped_count()`. New blocks become **new chunks** (one per level that needs blocks). `voxel_count()` is not updated |
| `propagate()` | recomputes the nodes that carry NEEDS_UPDATE from their children (CUDA `propagate`), level by level on the GPU; nothing to do without pending updates. Without `propagate_now` the statuses are inconsistent until it runs |
| `pending_update_count()` | reachable nodes with NEEDS_UPDATE (0 after `propagate()`), read back and walked on the host |
| `memory_usage()` | `garbage_blocks[level]` (blocks that lost their parent pointer, found by a walk) and `chunks` |
| `check_tree()` | the status rule "equals the rule applied to the children" now only applies to nodes with PART (a node without PART may own stale children), in a probabilistic tree it ignores STATIC / DYNAMIC (a dynamic update marks nodes DYNAMIC where the build says STATIC); unreachable blocks are a problem only while no insert replaced a child pointer |

## Algorithm (a different schedule than CUDA, the same result)
Insert: (1) ids sorted and made distinct on the host. (2) **Walk** kernel per voxel: from the root while the node has PART and the level is above 1, setting NEEDS_UPDATE on every visited node and the end node; `info[i]` = end level, node address, kind (0 = the leaf exists, 1 = new blocks needed) and a counter of end nodes that still own a child block (those blocks become garbage). (3) Per level 0..13 a **heads** kernel marks the first voxel of every new block (voxels with the same `id >> 3(level+1)` and kind 1 and end level above the level share the block), an exclusive scan gives block indices and totals; one new chunk per level. (4) From level 13 down to 0: heads + scan again, then the **link** kernel: the head voxel of a new block initialises its 8 nodes (CUDA `insertNode`) and writes PART and the child address into its parent (the node in the new block one level up, or the node the walk ended on): one block per parent, one head per block, so every node has exactly one writer and no atomics are needed. (5) **Leaves** kernel: new leaf = DYNAMIC | datum, existing leaf = (status & ~(occupancy bits | PART)) | datum, atomics on the leaf word only.
Propagate: **top-down** one dispatch per level 14 .. 2 over the work list of flagged PART nodes (a child without occupancy bits takes over from its parent, a child without PART loses the flag, a flagged PART child joins the next list; on level 2 every PART child joins because level 1 nodes are always recomputed), then the **level 1** kernel (invalid leaves take over from the node, the node is recomputed from its leaves), then **bottom-up** from level 2 to 14 (the node is recomputed from its children, flag cleared). No busy waiting; the lists are sized from the counts read back per level.
**The two node rules** (`octree_dyn.glsl`, selected by `OCT_PROB` in the `_det` / `_prob` wrappers of every shader): deterministic "taking over" = every bit except PART / LAST_LEVEL from the parent (so STATIC / DYNAMIC are copied), recompute = CUDA `getNewStatus` (STATIC / DYNAMIC OR-ed, LAST_LEVEL on level 1). Probabilistic "taking over" = the occupancy of the parent and the status UNKNOWN, recompute = maximum occupancy of the children, PART unless all children have exactly that occupancy and none has PART, status = (status without PART and occupancy bits) | PART? | UNKNOWN; LAST_LEVEL, STATIC and DYNAMIC are not recomputed. A probabilistic tree built by inserts therefore differs from a fresh build in more than STATIC / DYNAMIC: occupied leaves are UNKNOWN there (CUDA `_updateStatus`) and STATIC-only in the build (CUDA `setOccupied`).
Differences from CUDA: ids are deduplicated and sorted on the host (CUDA requires sorted distinct ids), one chunk per level and insert instead of one allocation, the walk marks nodes with atomics instead of "the first thread of a shared path", propagate is a wavefront instead of the load balanced queue.

## Verification
- Reference: [octree_dynamic_reference.h](../../../tests/reference/octree_dynamic_reference.h) (own recursion on the memory tree with flags, stale blocks and garbage counts, both kinds), 7 deterministic and 5 probabilistic CPU cases whose expected trees were derived by hand ([Analysis](../../Analysis/2026-10-31_s6d_design.md#progress)); mutation check of the reference: 25 mutations (15 deterministic, 10 probabilistic), 24 killed, 1 equivalent.
- `test_octree_insert.cpp` (6 cases, both kinds, GPU against the reference, every step: full node list incl. STATIC / DYNAMIC bits and child blocks, `check_tree`, no NEEDS_UPDATE left, garbage blocks per level): the empty tree and a single voxel (the values 142 / 158 / 132 of the hand derivation), 12 random sequences (start from the empty tree or a build, with and without a full 2^3 block, three extents, 5 steps with occupied and free batches, duplicates inside a batch, propagate after every insert or only explicitly), inserts into a uniform level 2 node of a 4^3 cube (1 + 8 garbage blocks, the other voxels stay occupied), invalid voxels / ids and an empty insert, probabilistic saturation at +-127 and UNKNOWN leaves counting as 0 (also in a built tree), collisions of a grown tree against a partner (both implementations, `min_level` 0 / 1 / 3) equal to the fresh union tree, and the occupancy structure equal to the fresh build.
- `test_octree_chunks.cpp` (S6d-0): the tree in several chunks per level behaves like the one-chunk tree.
- Mutation check of the GPU side ([tools/mutation/mutate_s6d2_insert.py](../../../tools/mutation/mutate_s6d2_insert.py), log in `tools/mutation/logs`): 51 mutations of the walk, heads, link, leaves, propagate-down / -leaves / -up kernels, the shared node rules (14 of them probabilistic), the host code and the `check_tree` rule: 45 killed (C9 in a second run, the pattern of the first one was wrong); 6 survive and are explained: H2 (the previous voxel creating is implied by the equal parent node), F2 (leaves never have PART), D4 / D5 (pushing fewer / more unflagged PART children changes nothing for a consistent tree; CUDA does it, later steps rely on it), C8 (the status rule on stale children: they are consistent in this scope, cut nodes arrive with S6d-3b), C4 (the host `unique`: duplicates are harmless on the GPU, the precondition "distinct" of CUDA is kept on purpose).
- `test_vulkan` 200 of 200 pass (RTX 4090, zero validation errors).

## Not verified / limits
No CUDA comparison (the reference is derived from the same reading: a shared misunderstanding would not be found, golden data are needed for that, Q5). Soft insert, `UPDATE_SUBTREE`, target levels above 0 and the free-space bounding box are not implemented (S6d-3b); the log-odds values of the datum (127 / -127) are the CUDA `getOccupiedData` / `getFreeData`, not the sensor model (+100 / -10 of `CommonValues.h`, which belongs to the sensor pipeline S6f). Garbage is never freed (`rebuild`, S6d-4). Insert batches are limited to `kMaxVoxels`; every insert allocates up to 14 chunks (one per level) and a long series of small inserts accumulates chunks (the walk of check_tree and the collision capacities grow with the number of chunks: a size / count policy belongs to S6d-4). Timings were not measured.
