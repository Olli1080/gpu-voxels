# S6d design: dynamic octree updates (insert, propagate, rebuild)

- **Date:** 2026-10-31
- **Question:** What exactly do the CUDA `insertVoxel` / `propagate` / `rebuild` do, and how do we port them on the faithful route (Q19, Q24: wavefront style, no balancer) in steps that are each testable against an independent reference?
- **Scope / non-goals:** semantics read from the CUDA sources (**inferred**, nothing was run under CUDA), design and sub-slice order. No code of S6d exists yet. The sensor pipeline (`insertVoxel` with free-space ray casting, `computeFreeSpaceViaRayCast`, Kinect) is S6f and stays out (Q6).
- **Status:** draft (design only)

## Evidence: what the CUDA code does (inferred)
**Insert** (`insertVoxel<SET_UPDATE_FLAG>(sorted ids, set data, reset data, n, target_level)`), input = Morton ids **sorted** (duplicates not allowed: the host asserts strict order) with one `set` and one `reset` datum per voxel:
1. *Count:* per voxel walk from the root down while the node has PART, to `target_level` or to the deepest existing node; remember (node, level). Voxels count only the nodes their left neighbour (in sorted order) does not already share: the **new blocks per level** (8 nodes each). With `SET_UPDATE_FLAG` every inner node on the path gets `nf_NEEDS_UPDATE` (the first thread of a shared path sets it).
2. *Allocate:* **one new allocation per insert** (`cudaMalloc`, kept in `m_allocation_list`): leaf blocks, then inner blocks of levels 1..n, each 128-byte aligned. Nothing is freed on insert.
3. *Init:* every new node = `insertNode` (inner: status `ns_DYNAMIC_MAP`, flag `NEEDS_UPDATE`; last-level inner: also `ns_LAST_LEVEL`; leaf: `INVALID_STATUS | DYNAMIC_MAP`; probabilistic: occupancy `INITIAL_PROBABILITY`).
4. *Set:* bottom-up per level, the leftmost voxel of a shared path takes the next new block, the node at `target_level` gets the datum, nodes above get `PART` and the child pointer. An already existing node at the target level is **updated** (`updateNode`), a new one **set** (`setNode`).
**Data semantics.** Deterministic: `status = (status & ~reset) | set`; hard / soft insert reset = `STATUS_OCCUPANCY_MASK | ns_PART` (the PART bit is cleared: **the subtree below is cut off but not freed**, the CUDA code says `TODO FREE TREE`); set = `ns_OCCUPIED` or `ns_FREE`. Probabilistic: a leaf is *updated* by adding the occupancy (clamped to `MIN..MAX_PROBABILITY`, UNKNOWN counts as 0) and `_updateStatus` derives the status; a new leaf is *set* to the value; an inner node without child pointer gets the occupancy; **soft** insert (`reset` without PART) keeps the subtree and, if the node has PART, sets `nf_UPDATE_SUBTREE` so that propagate applies the value to the descendants; `free_bounding_box` uses `nf_UPDATE_SUBTREE` in the reset data on purpose (do not set it).
**Propagate** (`propagate`, load balanced, `Propagate.cuh`): work items = blocks of 8 siblings. *Top-down:* an inner node with PART, not last level, with `NEEDS_UPDATE` (or inherited `UPDATE_SUBTREE`) pushes its children; a node whose status bits (free/unknown/occupied) are all 0 (freshly created) takes the parent's status except PART / LAST_LEVEL (**expanding a compressed node**); leaves with invalid status likewise; flags are cleared on nodes without PART. *Bottom-up:* when all eight siblings are clean, the parent gets `getNewStatus(or, and, level)` (probabilistic: max occupancy + status from it) and its `NEEDS_UPDATE` is cleared; not-ready blocks are pushed back (this is what makes the CUDA queue busy-wait style).
**Rebuild** (`needsRebuild`: `m_max_memory_usage != 0 && memory >= max`, default 200 MB; `internal_rebuild`): extract every voxel/cube and build a fresh tree, because inserts only add memory (cut subtrees and new allocations accumulate).

## Findings
1. **The tree grows in chunks, not in one buffer per level** (high; read). Our `Octree::Impl` holds exactly one chunk per level (`std::optional<Chunk>`, about 40 lines of `Octree.cpp` touch it: dump, check_tree, collisions, capacities of the wavefront buffers). Insert needs **several chunks per level**, and the traversals' capacities (sum of blocks of both trees per level) become sums over chunk lists. This is the first piece of work and a pure refactor with the 190 existing tests as safety net.
2. **Cut subtrees become garbage** (high; read): `check_tree` currently reports blocks that are not reachable from the root as a problem (`octree_build.md`). With hard inserts this is normal; the registry must track a reachable and a garbage count, `memory_usage` must say so, and `needs_rebuild()` can use "garbage fraction" in addition to the CUDA byte limit.
3. **Propagate can be a level-synchronous wavefront** (medium): top-down by levels (flagged blocks → their child blocks), bottom-up from level 1 up, one dispatch per level with no busy waiting; results are order independent because a parent depends only on its eight children. The reference must be the plain recursive "fresh tree from the final voxel set" **and** the CUDA rules for flags, since after propagate every flag is clear.
4. **Equality tests:** a propagated tree after any sequence of hard inserts equals `OctreeReference(union set)` node by node for deterministic trees when the sets are disjoint from cut regions; where an insert cuts a PART node the reference needs a *set* operation (replace the subtree by one node), so the reference gets `insert(voxel, datum, level)` with exactly the semantics above, written recursively and independently (the plain recursion cannot share code with the kernels).
5. A leaf "update" of an existing probabilistic voxel (log-odds add) is only observable through the occupancy; the status must follow `_updateStatus` (same rule as the S6b build for new leaves).

## Plan (sub-slices, each ends *Tested* in the sense of the definition of done)
| Step | Content | Tests |
|---|---|---|
| S6d-0 | Chunk lists per level (refactor, no behaviour change), reachable/garbage accounting in `check_tree` / `memory_usage` | all 190 existing tests unchanged; new: a tree built from two chunks per level (test hook) gives the same dump / collisions |
| S6d-1 | Reference: recursive `insert(voxel, datum kind, level)` + `propagate` rules for deterministic and probabilistic trees, mutation-tested first | reference vs hand-derived trees (insert into empty, into a uniform node, cutting a PART node, update of a leaf) |
| S6d-2 | GPU `insert` (deterministic, level 0, hard set, occupied / free), wavefront `propagate`, `check_tree` after each step | random sequences of inserts against the reference; insertion into pruned uniform regions; propagate after partial updates; duplicates and out-of-range ids |
| S6d-3 | Probabilistic update / set, soft insert and `UPDATE_SUBTREE`, higher `target_level` (free-space boxes) | as S6d-2 plus log-odds saturation, soft insert over a PART node |
| S6d-4 | `needs_rebuild()`, `rebuild()` (= extract + fresh build), memory limit as an option | rebuild equals a fresh build of the union set; garbage released |
Order matters: S6d-0 first, because everything after it allocates new chunks. S6d-1 can run in parallel to S6d-0 (different files).

## What was NOT verified
Everything above is read, not run: no CUDA toolkit use, no golden data. Open semantic points to settle while writing the reference: how CUDA treats a node that has PART and is *updated* at a higher level than its voxels (deterministic: reset removes PART, i.e. cuts); whether the "expanded" children of a uniform node keep their `DYNAMIC_MAP` bit after propagate (status mask `~(PART|LAST_LEVEL)` copies it); the unused `kernel_insert_setNodes` branch for `level == 0` nodes that already exist (they are updated in place and the voxel then counts as inactive).

## Recommendation / decision needed
Start with S6d-0 (refactor) and S6d-1 (reference) next; no user decision is needed for them. Decisions that come with S6d-3/-4: whether `needs_rebuild()` keeps the CUDA 200 MB default or uses the garbage fraction (proposal: both, configurable), and the public shape of `insert` (voxel list with datum per voxel vs two lists), to be settled with S6e (façade).
